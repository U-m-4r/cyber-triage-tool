# Frozen CSE-CIC-IDS2018 validation

This adapter is an explicit opt-in for official CICFlowMeter flow CSVs. It is not
a generic converter for arbitrarily named network columns. See
`test-results/issue-4/PROTOCOL.md` for the date-selection and validity policy fixed
before external inference, and `test-results/issue-4/REPORT.md` for actual results.

## Reproduce

Use the existing project environment and reviewed model acquisition procedure.
The selected two daily CSVs total 735,004,575 bytes. No PCAPs are needed. Raw files,
full exclusion ledgers, source-row demo manifests, exact prediction arrays and
audit databases remain in ignored `.test-artifacts/issue4/`.

```powershell
rtk proxy .venv/Scripts/python.exe -m pip install -r requirements/dev.txt -r requirements/external-validation.txt
rtk proxy .venv/Scripts/python.exe -m scripts.acquire_network_models
rtk proxy .venv/Scripts/python.exe -m scripts.acquire_external_dataset
rtk proxy .venv/Scripts/python.exe -m scripts.evaluate_external_network --chunk-size 25000 --overlap-db .test-artifacts/issue3/513da53c9db64dd9a545e980271dad37.sqlite
rtk proxy .venv/Scripts/python.exe -m scripts.verify_issue4 --serve
```

Use `scripts.prepare_external_demo` to build the same prediction-independent demo
without waiting for the full audit, and `scripts.render_external_reports` to
render the actual saved-case PDFs. The full evaluator also writes that identical
demo and records its checksum.

The overlap database is the read-only SHA-256 row audit generated by Issue 3's
`scripts.verify_network_models`; on a new machine use its newly generated path.
If it is unavailable, omit `--overlap-db`; overlap is explicitly NOT_RUN rather
than assumed absent. That option does not change the external population.
Evaluation requires the original manifest SHA-256 and refuses mutated sources.
Copy the Issue 4 output directory before repeating runs to preserve earlier runs.
Do not rerun Issue 3 evaluation just to change an external threshold or split.

## Feature and validity contract

`ml.external_dataset_adapter` v1 maps the eleven historical source aliases to the
exact model order without normalizing, imputing or recalculating a feature. Model
loaders, scalers, thresholds and feature dimensions remain unchanged. Ground truth
is explicitly mapped from known labels and is held outside inference frames.
Unknown labels are reported, never guessed. Measurements with missing/nonnumeric,
NaN, infinity or finite negative required values are excluded with original row
IDs and reasons. Model-transform overflow is also explicitly excluded for both
models before inference. Optional columns do not control numeric eligibility.
Finite zero durations, duplicate flows, outliers, conflicting-label vectors and
misclassifications are retained. No post-prediction row exclusions are allowed.

Source meanings and units are supported by official UNB documentation and the
historical CICFlowMeter source. The precise binary revision used to generate
both published datasets is unavailable: this is **CONDITIONALLY_COMPATIBLE**
cross-dataset measurement, not proof of identical flow construction. The preflight
report records source header mapping and rate-formula checks. Rate tokens rounded
by the original publisher are preserved, including scientific notation. Do not
rescale duration from microseconds or silently convert bytes into packets.

## Application workflow

Select **CSE-CIC-IDS2018 external network-flow CSV** in the Evidence tab, then select
the available detector and upload the generated manageable `demo.csv`. This sends
`dataset=cse-cic-ids2018` to `/api/analyze` and uses the controlled adapter. The
eleven source fields must be present; duplicate source headers and simultaneous
2017 target aliases are rejected. The external upload path rejects threshold
overrides, retains measured exclusion/compatibility metadata, and persists the
model ID and exact input measurements. Labels are not passed to inference or used
as risk indicators. Review label-based accuracy in the separate experiment report.

The normal per-request upload limit still applies; use the chunked evaluation
script for the full daily CSVs. Uploads never train or select a model based on
their outcomes. Predictions, triage scores and label-based metrics remain distinct.
Chunk-size invariance covers frozen detection predictions, model scores and
evaluation metrics. The legacy Isolation Forest triage policy normalizes severity
within an upload batch; it is not used to calculate external detection metrics.
The source dataset, adapter version and limitations also appear in saved-case PDF
reports. Disk-image YARA and PE malware analysis are separate, preserved workflows.

The HTTP demonstration binds loopback port 5049 and owns a fresh UUID database on
the dedicated MongoDB port 27018. Run React with `BACKEND_PROXY_TARGET` set to
`http://127.0.0.1:5049` and port 5219. It creates no production investigations.
No dataset/model download, training or external experiment is triggered by CI.

In a separate PowerShell terminal, start React with:

```powershell
rtk proxy powershell -NoProfile -Command '$env:BACKEND_PROXY_TARGET="http://127.0.0.1:5049"; npm --prefix frontend run dev -- --port 5219 --strictPort'
```

If the dedicated test MongoDB service is not already listening on 27018, create a
fresh test data directory and run the installed MongoDB server in another terminal:

```powershell
rtk proxy powershell -NoProfile -Command 'New-Item -ItemType Directory -Force -Path .test-artifacts/issue4/mongo'
rtk proxy 'C:/Program Files/MongoDB/Server/9.0/bin/mongod.exe' --dbpath .test-artifacts/issue4/mongo --port 27018 --bind_ip 127.0.0.1
```

That is the installed Windows server path used in this environment; use your
installed `mongod` path elsewhere. Reuse an existing dedicated test service rather
than attempting a second server on that port. The verifier owns a new UUID-named
database each run and never selects a production case database.
